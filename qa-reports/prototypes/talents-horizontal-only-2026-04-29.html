Сводка

Что меняется:

· canvas frame высота 560 → 392 pt — освобождает 168pt, теперь вмещается весь TalentsTabView (header + tabs + summary + canvas + reset) в один экран iPhone, без внешнего скрола.

· canvas overflow-y: hidden + overflow-x: auto — вертикальный скрол структурно невозможен, только горизонтальный.

· Tree height вычисляется так чтобы ТОЧНО влезть в frame: rowPitch = (frameHeight - 2 × padding) / (rowCount - 1). Для frame=392, padding=16, 6 рядов: rowPitch ≈ 72pt. Ноды 64pt с 8pt зазором по вертикали.

· Tree width остаётся натуральным от xMinGap=76 / minSameRowDx. Для warrior с min dx=120bp: width ≈ 608pt → горизонтальный скрол ~240pt.

Trade-off: вертикальная плотность увеличивается (rowPitch с 80 → 72). Связи между рядами становятся короче, но всё ещё читаются — orthogonal routing остаётся.

Открытый вопрос: при добавлении 7-го или 8-го ряда (если backend расширит дерево), rowPitch ужмётся до 60pt → ноды начнут касаться. Для текущей спеки 6 рядов запас есть.
