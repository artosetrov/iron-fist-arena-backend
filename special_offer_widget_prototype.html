Что ещё стоит учесть при реализации

+
Контент-модельКонтракт карточки: title, subtitle, items[{id, icon, qty, rarity}], oldPrice, newPrice (или FREE), discountPct, purchased/max, ctaLabel. Никаких «0 gold» из локали — FREE рендерится клиентом, если newPrice == 0.
+
CTA label«CLAIM» для FREE, «BUY» для платных, «CLAIMED» + disabled стиль если покупка совершена. Локализация через enum.
+
Rarity-рамки слотовИспользуем ItemCardView как источник правды для цветов rarity. Не создаём новый компонент слота — оборачиваем существующий в мини-размере (38pt).
+
Пак-артСейчас SVG-заглушка (сундук). В продакшене — ассет pack-starter.png из 05_UI_Backgrounds, загружается через CachedAssetImage.
+
Скроллинг рядаГоризонтальный ScrollView, snap на карточку, LazyHStack для производительности. Падинги: leading 16, trailing 16, gap 12.
+
A11yaccessibilityLabel: «Starter Pack, special offer, contains 3 large health potions, 500 gold, XP boost. Was 499 gold, now free. Claim.» Всё одним сообщением — VoiceOver не зачитывает пилюли по одной.
+
АнимацияТолько opacity-based feedback на press (как в DS). Никакого scale. Небольшой shimmer по золотой рамке раз в 6-8с — LiveOps-сигнал «обрати внимание».
+
СостоянияDefault → Press (opacity 0.85) → Claimed (gray overlay + чекмарк поверх hero) → Expired (оффер истёк, карточка disabled с таймером 00:00).

Prototype · Hexbound Design System tokens · нажми CLAIM — это просто HTML, реальная логика появится после твоего OK на дизайн.
