Hexbound — Unified Card v2 (Historical Prototype)

Historical design iteration from the card-system exploration, retained as audit context rather than current component guidance.

01 — Полный аудит: 9 проблем

❶ Level badge = цифра без смысла

"1" в круге — уровень? номер карточки? размер команды? Пользователь должен выучить. Нужен якорь.

❷ Горизонтальная list-карта

OpponentCardView — горизонтальный ряд. Это ДРУГОЙ паттерн среди вертикальных карточек. Нет унификации.

❸ 3 дублированных кода

ArenaOpponentCard + DungeonBossCard = идентичная структура, два файла. Hero card = ещё один вариант.

❹ Attack+Defense = шум

В арена-карте: Attack pill + Defense pill. Но Difficulty badge уже суммирует всё это. Дубль → перегруз.

❺ W/L + WR% = дубль

В list-карте: показываем и "12/8 W/L" и "60% WR". Одно и то же. Оставить только WR%.

❻ Boss "1" в кружке = ???

bossNumberBadge — просто число в круге. Без контекста "STAGE" пользователь не понимает что это порядковый номер стадии.

❼ Нет WIN/LOSS в истории

В History и Revenge вкладках карточки не показывают результат боя. Пользователь не видит "я победил или проиграл?"

❽ Tap-ambiguity: fight vs view

Тап по карточке = ? Открыть профиль или начать бой? Нет явной affordance. Текущий подход (тап = carousel select) неоднозначен.

❾ Нет injured state у героев

Герой с 5% HP выглядит как герой с 100% HP в списке выбора персонажа. Нет визуального сигнала "нужно зелье".

✅ Решение ❶ + ❻

LevelBadge → добавить "LVL" микро-лейбл. Boss → заменить на StageBadge с "STAGE" подписью.

✅ Решение ❷ + ❸

Единый CharacterCard (вертикальный портрет) для всех контекстов. List view → 2-колоночный grid из вертикальных карт.

✅ Решение ❹ + ❺

Убрать Attack/Defense pills. Убрать W/L. Оставить только WR% как единственный доп. сигнал.

✅ Решение ❼

History карта: top-right badge = WIN (зелёный) / LOSS (красный). Простой цветовой сигнал результата.

✅ Решение ❽

Карта + отдельная ActionStrip снизу. Тап по карточке = профиль/детали. ActionStrip "⚔ FIGHT" = бой. Намерения разделены.

✅ Решение ❾

HP bar на героях: если HP < 30% → красная рамка (danger glow) + иконка потиона как overlay.

04 — 2-колоночный Grid (iPhone 375pt)

Почему grid, а не список

Карточки — это визуальные объекты (портрет персонажа). Ценность приходит от арта, не от текста. 2-колоночный grid на 375pt даёт карточки ~165pt шириной — достаточно для читаемого арта. Это то, как работают Clash Royale, AFK Arena, Mobile Legends — все card-based мобильные игры. Horizontal scroll carousel → grid upgrade.

Единая структура данных для CharacterCard

Предлагаю добавить enum CharacterCardContext в CardLevelBadge.swift (или новый CardContext.swift):

arena(difficulty: OpponentDifficulty) — right badge = difficulty, primary = rating, secondary = WR%
dungeonBoss(state: BossState, stage: Int) — right badge = stage, primary = HP, secondary = drops
heroManagement(isSelected: Bool) — right badge = nil, primary = rating, secondary = HP+STA bars
battleHistory(result: BattleResult) — right badge = WIN/LOSS, primary = rating, secondary = WR%

Один компонент, четыре контекста.
