## Паттерны и уроки

### 1. Shared Wallet Migration — финальный отголосок в admin (Scanner False Negative)

**Что случилось:** Вчера (2026-04-09) был массовый фикс `character.gold → user.gold` в 7 коммитах по backend. Сегодня Vercel билд admin упал на TS2353: `admin/src/actions/players.ts:139` всё ещё использовал `prisma.character.update({ data: { gold } })`.

**Корневая причина:** Oracle scanner проверял паттерн `character\.gold\b` (свойство через точку), но не ловил **Prisma update-форму** `prisma.character.update({ data: { gold: ... } })` — там `gold` это ключ объекта, а не свойство переменной.

**Что обновлено:**
- `oracle/scripts/check_async_await.sh` — новая проверка: `grep -A3 'prisma\.character\.update'` + фильтр `\b(gold|gems)\s*:`. Теперь ловит и проперти-доступ, и Prisma data-блок.

**Проверено:** scanner теперь чист на admin/src/ после сегодняшнего фикса. Исторический паттерн поймался бы до коммита.

### 2. Constant Drift iOS↔Backend — превращено в CI guard (Recurring Manual Fix)

**Что случилось:** CRIT-01 (freePvpPerDay), CRIT-02 (daily login table), CRIT-03 (HP/XP hierarchy) — все три критических бага из плейтеста были по сути одной проблемой: iOS хранил захардкоженные значения, которые расходились с `balance.ts`.

**Корневая причина:** Paста между iOS и backend при итерациях балансировки. Старый `AppConstants.swift` использовался как fallback, но становился stale.

**Что сделано:** W1.D5 — добавлен CI guard `scripts/check_ios_backend_drift.sh` + интегрирован в `preflight_check.sh`. Теперь запрещает новые объявления `freePvpPerDay/maxStamina/pvpStaminaCost/xpPerLevel` в AppConstants без `// DEPRECATED` маркера. Это **канонический пример self-healing infrastructure** — паттерн бага превращён в механический блок.

**Побочный эффект:** W1.D4 автогенерация `BALANCE_CONSTANTS_AUTO.md` теперь даёт single source of truth для документации балансировки. Ручной `BALANCE_CONSTANTS.md` остался как куратор.

### 3. IntegratedCharacterCard unification — reusability rule применён

**Что случилось:** `HeroIntegratedCard.swift` (362) и `OpponentIntegratedCard.swift` (338) удалены → слиты в `IntegratedCharacterCard.swift` (401). Обе карты были 80% одинаковы (аватар + статы + capabilities); различались только action-кнопками снизу.

**Почему это правильно:** Правило #1 проекта — "reusability first". Два параллельных компонента для Hero/Opponent нарушали его годами. Теперь один компонент с `CharacterCardConfig` + slot для actions.

**Что обновлено:** Принцип уже закреплён в checked-in слое через общий `IntegratedCharacterCard` и соседние design-system / UI unification docs. Само правило не меняется — это уже устойчивый проектный принцип.

### 4. Сканер метрик — two false positives (Scanner False Positive)

**Что случилось:** `gather_metrics.sh` отчитывался:
- **96 junk files** — на самом деле все в `backend/node_modules/.prisma/client/` и `backend/.next/` (результат esbuild/pnpm dedup, не наш мусор)
- **3 UNSAFE bare theme tokens** — все три оказались системными: `.foregroundStyle(.white)` (x2) и `.background(.ultraThinMaterial, ...)`. Regex `\.\(\.?(white|...)\b` требовал буквального `.(` перед цветом, но в `foregroundStyle(.white)` перед скобкой буква `e`, не точка — фильтр не срабатывал.

**Что обновлено:**
- `gather_metrics.sh`: junk-поиск исключает `node_modules/.next/build/DerivedData`
- `gather_metrics.sh`: regex для сисколоров переписан на `\(\.?(white|...)` + добавлено исключение `ultraThinMaterial|thinMaterial|regularMaterial|thickMaterial|ultraThickMaterial|bar`

**Верификация:** после фикса — 0 junk, 0 unsafe tokens. Чисто.
