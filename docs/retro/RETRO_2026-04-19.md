## Паттерны и уроки

### 1. CI паттерн «regenerate BALANCE_CONSTANTS_AUTO» случился дважды за день

**Что произошло:** Коммиты `049dd2f` и `3630a15` оба исправляли один и тот же CI-failure — `npm run docs:balance:check` падал, потому что при изменении `backend/src/lib/game/balance.ts` разработчик не прогонял `npm run docs:balance` локально. Два повторения одной и той же ручной починки за сутки — явный сигнал что правило не документировано в preflight-чеклисте.

**Корень:** Baseline CI ожидает, что сгенерированный `docs/06_game_systems/BALANCE_CONSTANTS_AUTO.md` всегда в sync с `balance.ts`. Генератор существует (`npm run docs:balance`), но запускается только вручную.

**Fix:** Добавлен пункт в `gatekeeper/SKILL.md` §6 (Documentation Updates) и в `oracle/SKILL.md` §12 (Deploy Awareness): при изменении `balance.ts` нужно прогнать `npm run docs:balance` и коммитить сгенерированный файл в том же изменении.

### 2. CI path-filter дрейф — workflow тихо отключался

**Что произошло (`40617f0`):** `.github/workflows/ci.yml` продолжал триггерить `docs:balance:check` только на изменения в `docs/04_BALANCE/**` — но эту папку давно переименовали в `docs/06_game_systems/`. CI выглядел «зелёным» потому что нужная job просто не запускалась на правках документа.

**Fix:** Добавлена новая секция `§6b CI Workflow Path Filters` в `gatekeeper/SKILL.md`. При любом изменении `.github/workflows/*.yml` — каждая запись в `paths:` должна быть проверена на существование в файловой системе.

### 3. Next.js prerender-crash из-за module-scope Supabase client

**Что произошло (`e2b5185`):** `backend/src/app/reset-password/page.tsx` содержал top-level `const supabase = createClient(process.env.SUPABASE_URL!, ...)`. При `next build` без полной env-пары Supabase крэшил всю сборку с "supabaseUrl is required" — даже в окружениях, где сама страница никогда не рендерится.

**Fix:** Lazy-init паттерн через `getSupabase()` внутри компонента. Правило добавлено в `oracle/SKILL.md` §11a с grep-шаблоном для сканирования `backend/src/app` на `createClient(` вне функции.

---

### 4. Новый паттерн: raw-SQL fallback для boot-critical read endpoints

**Что появилось (`16fe0b5` + `0658532`):** Эндпоинт `/api/characters` GET теперь:
1. Сначала пробует `prisma.character.findMany` с явным `select`.
2. При любой ошибке падает в `$queryRaw` c полным column mapping (snake_case → camelCase) как типизированный `CharacterListRow[]`.
3. После этого прогоняет HP/stamina regen через `Promise.allSettled`, чтобы одна битая строка не обнуляла весь список.
4. `accountGold/accountGems` тоже обёрнуты в try/catch — user-wallet как compatibility sugar, не блокирует экран.

**Почему:** Запуск приложения начал 500-ить у части пользователей после недавней миграции схемы — generated Prisma client оказывался недолго рассинхронизирован с живой БД между apply-migration и Vercel redeploy.

**Правило:** Паттерн зарезервирован для endpoint-ов, падение которых блокирует загрузку приложения. Write endpoints остаются fail-loud. Документировано в `oracle/SKILL.md` §11b.

### 5. Nullable-field миграция требует grep всех downstream потребителей

**Что произошло (`ed3001d`):** `PvpMatch.player2Id` стал nullable для поддержки бот/босс-матчей. Prisma типы ушли с `string` на `string | null` — admin-страница `/matches` дереференсила `match.player2.characterName` без null-check, tsc зарубил admin build.

**Fix:** Правило добавлено в `oracle/SKILL.md` §11c: при любой смене `required → nullable` в `schema.prisma` обязательна команда

```bash
grep -rn "\.<field>" admin/src backend/src --include="*.ts" --include="*.tsx"
```

и поправка каждого call-site, не только тех, что ловит tsc на текущем билде.
