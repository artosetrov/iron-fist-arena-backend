## Паттерны и уроки

### 1. `try?` → do/catch + logging

В `MailMessage.swift` заменён `try?` на do/catch с `print("⚠️")`. Это правильный паттерн — молчаливый `try?` прячет ошибки декодинга. **Урок:** `try?` в парсинге данных — антипаттерн. Guardian должен флагать `try?` на JSON decode.

**Не обновляю скрипты сейчас**, т.к. `try?` в принципе легитимен в Swift (необязательные значения) — но стоит мониторить в следующих ретро, повторяется ли паттерн.

### 2. Клиентский attackPower в Opponent.swift

Добавлен `var attackPower: Int` в Opponent модель с формулой по классам. **Потенциальный конфликт с правилом** "server-authoritative: client must NOT calculate combat results, rewards, ratings, economy values, or balance formulas". Однако это **display-only** значение для preview, не влияющее на бой — серверная логика по-прежнему определяет исход. Допустимо, но стоит отметить: при изменении баланса нужно обновить и клиентскую формулу.

### 3. BattlePassService: Bool → typed errors

`claimReward()` перешёл с `return false` на `throws BattlePassClaimError`. Хороший паттерн — типизированные ошибки дают UI возможность показать контекстные сообщения. Стоит применять к другим сервисам.

### 4. Создан backend/CLAUDE.md

Новый rules-файл для бэкенда: TOCTOU, atomic increments, N+1, rate limiting, minigame limits, error handling. Важный шаг — теперь бэкенд-правила в одном месте.

### 5. Dead code cleanup

Удалены `CombatService.swift` (клиентский боевой расчёт, нарушал server-authoritative) и `FeatureFlagService.swift`. Также удалены старые .md файлы (ART_STYLE_GUIDE, TESTFLIGHT_GUIDE, UI_PR_CHECKLIST). Корректная чистка.

### 6. Opponent model: 6 статов + armor в matchmaking

Все 3 matchmaking-эндпоинта (opponents, find-match, fight) теперь select'ят str/agi/vit/int/wis/luk. Дублирование select-списков в 3 файлах — потенциальный риск рассинхрона. Стоит рассмотреть shared `opponentSelect` const.
