## Паттерны и уроки

### 1. (2b — Scanner FN) Hardcoded stale backend URL в auth-роуте

**Что произошло:** Block 187 — `backend/src/app/api/auth/forgot-password/route.ts` содержал `iron-fist-arena-backend.vercel.app` как fallback-хост для построения password-reset URL. В средах без `NEXTAUTH_URL` route отправлял ссылки на устаревший деплой.

**Root cause:** Скопировано из раннего прототипа; ни oracle-scanner, ни gatekeeper не проверяли hardcoded legacy URLs в API-роутах.

**Fix:** Заменено на `api.hexboundapp.com` (canonical production origin), добавлено regr. покрытие.

**Rule added:** Oracle SKILL.md → Section 9a. Scanner: `grep -rn "vercel\.app\|iron-fist" backend/src/`.

---

### 2. (2b — Scanner FN) Отсутствующий 409-guard при email-коллизии

**Что произошло:** Blocks 189–190 — `/auth/link-account` и `/auth/sync-user` не имели явного pre-flight duplicate-email check. При коллизии Prisma бросал P2002 (unique constraint), который route не перехватывал → 500 вместо 409.

**Root cause:** Паттерн "email uniqueness guard" не задокументирован; при написании роутов это поведение не проверялось.

**Fix:** Добавлен `findFirst({ where: { email } })` → `if (existing) return 409` перед `update` в обоих роутах + тесты на conflict path.

**Rule added:** Oracle SKILL.md → Section 9b.
