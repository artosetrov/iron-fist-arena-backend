## Паттерны и уроки

### 🐛 Scanner false negative — Test mock drift блокирует CI, не Vercel

**Что произошло (block-029):** `premium.ts` получил новый экспорт `PREMIUM_ENTITLEMENT_USER_SELECT`. Vercel production build прошёл зелёным — TypeScript не использовал этот экспорт в prod-пути. Но GitHub Actions запускает `vitest`, и два тестовых файла (`pvp-resolve.test.ts`, `dungeon-rush-resolve.test.ts`) мокали `@/lib/game/premium` без нового экспорта — роут падал с 500 внутри теста.

**Корневая причина:** Test mock и реальный модуль — разные контракты. Mock может быть подмножеством, но когда runtime-код в prod-пути начинает обращаться к новому экспорту, mock-only тест-среда ломается.

**Урок:** Добавление любого экспорта в `src/lib/game/*.ts` ОБЯЗАТЕЛЬНО сопровождается обновлением всех mock-файлов в `backend/tests/`, которые мокают этот модуль, в том же коммите.

**Действие:** добавлен раздел `### 5b. Test Mock Parity` в `gatekeeper/SKILL.md` + раздел `### 6. Shared Lib Module Contracts` в `oracle/SKILL.md`.

---

### 🐛 TypeScript reward type widening → Vercel build failure (block-028)

**Что произошло:** `shop/contraband/route.ts` имел локальный хелпер `generateLoot()` с возвращаемым типом `{ type: string; ... }[]`. Это не было проблемой до введения `reward-grants.ts` — как только `grantRewardEntries()` потребовал `readonly RewardGrantEntry[]`, TypeScript не смог привести `string` к строгому union `'gold' | 'gems' | 'xp' | 'item' | 'consumable'`. Vercel-деплой заблокирован.

**Корневая причина:** Локальный тип «достаточно близкий» не компилируется со строгим shared-контрактом.

**Урок:** Любой reward-shaped объект в backend-роутах должен явно аннотироваться как `RewardGrantEntry`, а не `{ type: string }`.

**Действие:** добавлен `Reward type widening` checklist в `oracle/SKILL.md` раздел 6.
