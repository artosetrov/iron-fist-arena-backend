## Паттерны и уроки

### 🔁 Recurring manual fix — `private` на extracted struct ломает билд

- `6244d17`: после split `GoldMineDetailView.swift` → `GoldMineCards.swift` структуры `MineShaftCard` и `LockedMineCard` остались `private`, из-за чего callers в исходном файле теряют к ним доступ.
- **Правило**: при extract struct/view в отдельный файл снимать `private` (оставлять default internal или явный `public`). Актуально для всей refactor-серии.
- **Действие**: документирую в ретро. Скан для этого сложно сделать точным (слишком много false positives на корректный `private` внутри single-file); держим в памяти как ручное правило.

### 🧩 New convention — soft limit на размер View-файла

- За один день 7 файлов в диапазоне 1170–2034 строк были раздроблены. Паттерн «монолит копится до тех пор, пока не становится нечитаемым» — системный.
- **Действие**: добавлен `## 10. Monolithic Swift View files (>1000 lines)` в `guardian/check_design_system.sh`. Soft-warn, не блокер. После сегодня — 0 файлов >1000 строк (максимум: GoldMineMiniGameView 945).

### ⚠️ Scanner false negative — `enum State` shadows SwiftUI.State

- `6244d17`: `TalentNodeView` объявлял `enum State: Equatable` внутри View-тела, что теневало `@State` property wrapper и ломало компиляцию. Fix — переименование в `NodeState`.
- **Действие**: добавлен `## 9. Nested 'enum State' shadows SwiftUI.State` в `guardian/check_design_system.sh`. Scanner уже ловит один оставшийся случай (`TutorialFightViewModel.swift:11` — pre-existing, не блокер, но при следующем касании этого файла — переименовать).

### 🐛 AppState dual-key mismatch — `combatResult` vs `combatData`

- `367327e`: после Interactive Combat юзер видел "Battle Failed — stamina was not consumed" вместо normal result modal. Причина: `handleTerminal` писал в `appState.combatData`, а `CombatResultDetailView` читает `appState.combatResult`.
- **Корневая причина**: параллельные state-поля для одного концепта. Classic combat писал в оба, interactive забыл один.
- **Действие**: задокументировано здесь; правило для будущих terminal-обработчиков — **всегда писать в оба** (`combatResult` для modal, `combatData` для downstream playback). Scanner-check сложен (нужен AST), оставляю как code-review checklist для Combat фичей.
