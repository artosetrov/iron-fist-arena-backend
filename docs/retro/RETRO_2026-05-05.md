## Паттерны и уроки

### 1. Static stored properties on generic types — новый правил-уровневый сигнал

**Что произошло.** Унификация в `6b5a72d` принесла `static let premiumAccent: Color = ...` на новый generic `struct ActiveSlotTile<Overlay: View>`. Swift это не компилирует:

```
error: Static stored properties not supported in generic types
```

Хотфикс `20cdcea` пришёл через 62 минуты. Это первый зарегистрированный инцидент такого рода в проекте.

**Корень.** На non-generic типах `static let` — идиоматический способ держать общие константы. При добавлении дженериков (например, `ViewBuilder` overlay-параметра) каждый существующий `static let` молча становится build break'ом.

**Что сделано.**

- Добавлено правило 11 в `.skills/skills/guardian/SKILL.md` — Static Stored Properties on Generic Types (с пример-кодом, anti-pattern, ссылкой на инцидент).
- Добавлен scanner в `check_design_system.sh` секция 11 — awk парсит generic-типы (`struct/class/enum/actor Foo<...>`) и ловит `static (let|var) X: T = ...` внутри их тела. Computed (`static var X: T { ... }`) пропускаются. Проверено на синтетическом тест-файле — ловит правильно.
- Добавлен раздел "Swift Generics — No `static let` Stored Properties" в `docs/09_rules_and_guidelines/DEVELOPMENT_RULES.md` с примером и ссылкой на коммит.

### 2. Orphan Swift files — silent dead code on disk

**Что произошло.** Коммит `6b5a72d` отметил, что `Hexbound/Hexbound/Views/Hero/Talents/ActiveSlotsBar.swift` должен был быть удалён (по `wiki/log.md:497`), но файл физически остался: 0 ссылок в pbxproj, 0 call sites, только упоминание в комментарии `TalentsSummaryCard.swift:6`.

**Корень.** Blacksmith ловит "Swift files missing from pbxproj", но не различает "забыли добавить" vs "забыли удалить". А orphan-сценарий легко теряется в очереди ручных задач.

**Что сделано.**

- Добавлена секция 9 в `.skills/skills/gatekeeper/scripts/preflight_check.sh` — orphan check: для каждого `.swift` в `Hexbound/Hexbound/` считаем pbxproj refs и не-комментарий call sites. 0+0 = orphan, выводится с инструкцией `rm <path>` (run from Mac).
- Подтверждено на текущем состоянии: `ActiveSlotsBar.swift` корректно ловился как orphan и в этом cleanup-pass уже удалён из working tree.
- Добавлен раздел 4b в `.skills/skills/gatekeeper/SKILL.md` с описанием паттерна, инцидента и шагов на удаление.
