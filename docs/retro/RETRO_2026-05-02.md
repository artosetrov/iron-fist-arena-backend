## Паттерны и уроки

### 1. Cache key версионируется одновременно с миграцией формы данных

Когда Prisma-миграция меняет **содержимое строк** (новые координаты, переименованные enum'ы, soft-delete легаси), endpoint, кеширующий эту таблицу, обязан в **том же коммите** бампнуть версию ключа кеша. Иначе тёплый кеш Vercel продолжает отдавать старый payload, и клиент рендерит контракт, которого в БД уже нет.

В этом коммите (`18ac4fa`) `/api/passives/tree` ушёл `v4 → v5` синхронно с `repos_passive_positions_for_lane_layout`. Без бампа iOS получил бы старые координаты и перекрыл половину канваса.

**Куда добавлено:** `oracle/SKILL.md §14 Cache Key Versioning on Data-Shape Migrations (2026-05-02)` — review-чеклист для PR'ов с UPDATE/ALTER + endpoint с `CACHE_KEY` / `unstable_cache`.

### 2. Padding фиксированно-координатного канваса = ceil(nodeSize/2) + buffer

Когда SwiftUI-канвас раскладывает узлы по серверным `(x, y)` на фиксированном диапазоне `[0, W] × [0, H]`, инсет канваса должен быть **не меньше половины ноды + 4pt буфер**. Иначе ноды на `x=0` / `x=W` рендерятся центрами впритык к краю и обрезаются.

Конкретно: после lane-миграции координаты упёрлись в крайние значения, а `nodePadding` оставался 16pt с момента когда ноды стояли далеко от краёв. Полу-нода 28pt → нужен padding ≥ 32pt.

**Куда добавлено:** `guardian/SKILL.md §10 Fixed-Coord Canvas Edge Padding (2026-05-02)` — формула + review-trigger для `*Canvas.swift` + рекомендация: при ревью coord-миграции отдельно пере-проверять iOS-инсет (backend-only repos может молча сломать клиентскую раскладку).

### 3. Endpoint-superset → client-side filter — задокументировать контракт

`/api/passives/tree` возвращает ноды для **всех 4 классов**, клиент фильтрует по `character.classRestriction`. Без явной записи контракта следующий consumer (admin, web-просмотрщик, новый клиент) получит overlapping cells. Внутри §14 oracle добавлен «companion rule»: superset-endpoint требует либо server-side фильтра, либо явной пометки в `API_REFERENCE.md`.
