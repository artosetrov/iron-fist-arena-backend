## Паттерны и уроки

### 1. Shared Wallet Migration — каскадные поломки (Scanner False Negative)

**Что случилось:** При миграции `character.gold` → `user.gold` потребовалось 7 отдельных коммитов для исправления 15+ файлов. Каждый фикс выявлял новые пропущенные ссылки.

**Корневая причина:** Oracle scanner не проверял ссылки на `character.gold`/`character.gems` — эти паттерны не были в чеклисте.

**Что обновлено:**
- `oracle/SKILL.md` — добавлена секция "3b. Shared Wallet Model" с запрещёнными и правильными паттернами
- `oracle/scripts/check_async_await.sh` — добавлена проверка #5 "Shared Wallet Violations" (grep character.gold/gems)

### 2. Undefined userId — повторяющийся ручной фикс (Recurring Manual Fix)

**Что случилось:** В 4+ роутах использовалась переменная `userId`, которая не существовала в scope. Правильно — `user.id` (из деструктуризации auth результата).

**Корневая причина:** Copy-paste между роутами, где naming convention отличалась. TypeScript strict mode должен был поймать это на этапе build.

**Действие:** Не требуется обновление сканера — это TypeScript compile error. Если build проходился с `ignoreBuildErrors: true` в прошлом, это объясняет пропуск. Правило уже есть в oracle ("No `ignoreBuildErrors`").

### 3. Дублирующиеся коммиты

**Что случилось:** Две пары коммитов с идентичными сообщениями:
- `dbc5b1c` и `b7a636e` — "fix(test): add missing lossStreakGoldMultiplier"
- `77c1527` и `b6a1008` — lazy-init Supabase

**Вероятная причина:** Git workflow issues — возможно, re-apply после merge conflict или push rejection.

### 4. Массовая очистка репозитория

**Что случилось:** Удалены ~14,800 строк прототипов, старых аудитов, hexbound-landing assets из основного repo.

**Это хорошо.** Репозиторий стал чище. Прототипы и landing assets не должны были быть в monorepo.
